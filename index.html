Suíte de regressão do portal de recarga

Regressão do painel administrativo de um portal de gestão de recarga de veículos elétricos. Ela confere se as telas abrem, se as ações de negócio funcionam e se nenhuma chamada de API por trás delas falha.

ver no GitHub →

Destaques

  • Checagem de API, não só de UI. A suíte intercepta as respostas de rede durante downloads, relatórios e telas de detalhe, e o teste falha se o backend der erro. Assim ela pegou bugs reais que uma checagem visual deixaria passar.
  • Teste de permissão. Para cada perfil, a suíte tenta abrir por URL direta todas as rotas fora do escopo e garante que nenhuma delas abre.
  • Um conjunto de testes, 4 perfis. Page Object Model com uma matriz de telas e fluxos para cada perfil de acesso.
  • Login com MFA (TOTP) centralizado, sessão isolada por perfil e relatório HTML com evidências a cada execução.

Dashboard de qualidade no Grafana

Criei por iniciativa própria um painel de bugs, incidentes e deploys acompanhados contra os SLAs da empresa: 2 dias para incidentes e 5 para bugs. Os dados saem do Azure Boards sem trabalho manual além de mover o card. Apresentei o projeto à gerência comercial.

ver no GitHub →

Como funciona

  • Uma consulta WIQL busca só os cards com as tags BUG, INCIDENTE ou MELHORIA da área monitorada.
  • O status vem da coluna do board. Quando o card entra em homologação, conta como fechado. Quando entra em produção, o deploy é registrado automaticamente.
  • O upsert idempotente mantém o banco igual ao estado atual do board e remove os itens que saíram do filtro.
  • O token de acesso é somente leitura e fica nos GitHub Secrets, nunca no código.

Painéis

  • Bugs, incidentes e melhorias abertos
  • Tempo médio até fechar
  • Novos cards por mês e distribuição por tipo
